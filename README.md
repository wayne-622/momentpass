# 瞬传 · 在线直连 / 离线投递

两种文件传输模式并存：

| 模式 | 发送端是否需要保持页面开启 | 文件是否经过服务器 | 适用场景 |
| --- | --- | --- | --- |
| **在线直连（P2P）** | 必须，两端同时在线 | 否，仅握手经过信令服务器 | 两台设备同时在线，注重隐私 |
| **离线投递（服务器暂存）** | 否，上传完成即可关闭页面 | 是，暂存在你自建的中转服务器 | 对方不在线、跨时间取件 |

接收端**不需要手动选择模式**：输入分享码后先尝试点对点连接，12 秒内连不上（或发送端不在线）会自动查询中转服务器，找到离线包裹则改为流式下载（浏览器原生下载，直接写磁盘，不占页面内存，移动端大文件同样适用）。

---

## 文件说明

- `瞬传_P2P_跨设备文件传输.html`：前端页面（自包含单文件）
- `server.js`：离线投递中转服务器，**零第三方依赖**，仅需 Node.js 16+
- `relay-data/`：运行后自动创建，存放暂存文件（可随时整体删除）

---

## 快速开始

### 1. 安装 Node.js

到 https://nodejs.org 安装 LTS 版本（16 或以上），安装后命令行执行 `node -v` 能看到版本号即可。

### 2. 启动服务器

在本目录打开命令行，执行：

```bash
node server.js
```

看到以下输出表示成功：

```
瞬传中转服务器已启动
  本机访问： http://localhost:3000
  暂存目录： ...\relay-data
  保留时长： 24 小时
```

### 3. 打开页面

浏览器访问 **http://localhost:3000** （注意：要用服务器地址访问，离线投递才可用；直接双击 html 打开只有在线直连模式）。

## 离线投递操作流程

**发送端：**

1. 选择文件 / 文件夹
2. 点击「**离线投递**」（不是「生成分享码」）
3. 文件上传到服务器后，页面显示分享码和二维码，状态为「已暂存服务器 · 对方凭码随时可取」
4. 此时可以关闭浏览器 / 关机（服务器保持运行即可）
5. 如需撤回，点「删除暂存文件」；也可等其自动过期

**接收端：**

1. 打开页面，输入分享码（或扫码 / 打开分享链接）
2. 页面先尝试直连发送设备，失败后自动显示离线包裹
3. 单文件点「下载文件」；多文件可「打包下载 ZIP」（保留文件夹结构），也可逐个下载

## 局域网使用（手机 ↔ 电脑，最常用）

1. 电脑运行 `node server.js`
2. 手机和电脑连同一个 Wi-Fi
3. 查看电脑局域网 IP（Windows 命令行执行 `ipconfig`，一般是 `192.168.x.x`）
4. 手机浏览器访问 `http://192.168.x.x:3000`
5. 若手机访问不了，检查 Windows 防火墙是否放行 Node（首次运行通常会弹窗，勾选"专用网络"允许）

## 公网部署（跨网络、对方随时可取）

离线投递要在任意网络下可用，服务器需要有公网地址。最简单的方式：一台云服务器（VPS）+ Caddy 自动 HTTPS。

```bash
# 1. 把 server.js 和 html 上传到 VPS，例如 /opt/shunchuan/
# 2. 安装 Node.js 16+，用进程管理器常驻（可选）：
npm i -g pm2
pm2 start server.js --name shunchuan
pm2 save && pm2 startup

# 3. Caddyfile（自动申请 HTTPS 证书，浏览器摄像头/剪贴板等 API 才完整可用）：
relay.example.com {
    reverse_proxy localhost:3000
}
```

之后两端都访问 `https://relay.example.com`。在线直连的信令仍默认使用公共 PeerJS 云，文件点对点传输；离线投递走你自己的服务器。

## 配置项（环境变量）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | 3000 | 监听端口 |
| `HOST` | 0.0.0.0 | 监听地址 |
| `RELAY_TTL_HOURS` | 24 | 暂存文件保留小时数，到期自动删除（服务每 10 分钟巡检，启动时也会清理一次） |

示例：保留 3 天、端口 8080：

```bash
# Windows PowerShell
$env:RELAY_TTL_HOURS=72; $env:PORT=8080; node server.js
# Linux / macOS
RELAY_TTL_HOURS=72 PORT=8080 node server.js
```

前端右上角「设置」中可单独填写**离线投递服务器地址**（留空 = 与页面同源），也可以改信令服务器（PeerServer）和 ICE/TURN 配置。

## 安全与隐私说明

1. **分享码即取件凭证**：8 位码（约 1.1 万亿种组合），拿到码的人就能下载暂存文件，请通过可信渠道告知对方。
2. server.js **没有账号和鉴权**，设计为个人/团队内网或自用 VPS 使用；公网暴露时建议放在反代后面加访问控制（如 Caddy basicauth），或自行扩展鉴权。
3. 不使用「离线投递」时，文件永远不会上传到服务器，在线直连模式的行为与原版完全一致。
4. 暂存文件以二进制形式存放在 `relay-data/<取件码>/`，到期自动删除；发送端也可随时手动删除。
5. 服务器磁盘需要容纳同时暂存的文件总量，请自行监控磁盘空间。

## HTTP API（供调试 / 二次开发）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/relay/ping` | 健康检查 |
| POST | `/api/relay/init` | 新建包裹，body：`{files:[{name,path,size,mime}], ttlHours?}`，返回取件码 |
| PUT | `/api/relay/:code/file/:idx` | 上传第 idx 个文件（原始字节流，header：x-name/x-path/x-size/x-mime） |
| POST | `/api/relay/:code/complete` | 全部上传完成，包裹转为可下载 |
| GET | `/api/relay/:code/meta` | 查询包裹文件清单 |
| GET | `/api/relay/:code/file/:idx` | 下载单个文件 |
| GET | `/api/relay/:code/zip` | 打包 ZIP 下载（store 不压缩，保留目录结构，支持中文文件名） |
| DELETE | `/api/relay/:code` | 删除包裹 |
